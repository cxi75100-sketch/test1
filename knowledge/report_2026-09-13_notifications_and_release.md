## 一、验收结果（TASK-039，`ncpu_api36`，release 包）

前置事实：该模拟器时钟为 UTC、时区 `persist.sys.timezone = GMT`（知识库此前记为 `Asia/Shanghai`，本轮更正）。时钟绝对值正确，因此这**恰好覆盖了"设备时区与校园不一致"这条分支** —— 下面第 1 个缺陷就是这样暴露的。

## 二、两个缺陷

### ISSUE-017 release 构建裁掉通知图标 → 「上课提醒」开启即失败（发布阻断）

- **现象**：在正式签名 release 包上点「上课提醒」立刻弹「开启失败，请稍后重试」，**通知权限弹窗根本不出现**。
- **排查路径**（值得复用）：先怀疑权限 → `dumpsys` 发现 `POST_NOTIFICATIONS` 未被请求过且无 `USER_SET`；手动 `pm grant` 后仍失败，排除权限 → 在协调器的 catch 里加一条开发日志，把异常显示到界面上 → 拿到 `PlatformException(invalid_icon, The resource ic_stat_school could not be found...)` → 对比 debug/release 包资源表，发现 debug 有、release 没有。
- **根因**：`drawable/ic_stat_school` 只被 Dart 代码按**字符串**引用，release 构建把它当无人引用的资源裁掉了。插件在 `initialize()` 阶段就解析图标，于是异常发生在请求权限之前。
- **为什么此前三个版本都没发现**：「APK 静态校验」只能证明文件存在于源码树，看不到打包时的裁剪；而 debug 包保留了该资源，因此所有 debug 验收都是正常的。
- **影响**：`v1.0.0` / `v1.0.1` / `v1.0.2` 的 release 包提醒功能**一直不可用**，用户只看到一句无解释的失败提示。
- **修复**：`android/app/src/main/res/raw/keep.xml` 用 `tools:keep="@drawable/ic_stat_school"` 显式保留。
- **验证**：release 包 `aapt2 dump resources` 能查到 `resource 0x7f08005e drawable/ic_stat_school`；装机后权限弹窗正常出现并走完全流程；到点通知的投递记录里 icon 正是该资源 id。

### ISSUE-018 提醒时间基准用设备本地时间，单条过期提醒清空整批排程

- **现象**：设备时区为 GMT 时，把一门**当天已经上过**的课纳入提醒范围后，待触发闹钟从 196 条变成 **0 条**，而设置页仍显示「已开启」、没有任何提示。
- **根因（两处叠加）**：
  1. **基准不一致**：规划器拿 `DateTime.now()`（设备本地时间）与课表挂钟时间（节次作息、学期日期）比较。设备时区落后于校园时，当天已过的课被判为未来，交给插件后被其"必须是将来的时间"校验拒绝；设备时区超前时，未来几小时的课会被误丢。
  2. **失败被放大**：排程实现先清空再逐条写入，任何一条抛异常都会中断整个循环，于是刚清空的排程再也回不来；而这条失败路径只记日志、不回滚「已开启」状态 —— 用户看到的是「已开启但没有任何提醒」。
- **修复**：新增 `campusWallClockNow()`（按 UTC+8 换算但保留挂钟分量语义，与设备时区无关）作为规划基准；新增 `futureReminders()`，排程前进插件之前再滤一次过期项。
- **验证**：同一失败场景修复后待触发闹钟为 **195 条**（正好排除那 1 条已过期的），logcat 中「排程失败」0 条。**修复前后对照在同一台模拟器、同一门课上完成。**
- 与 ISSUE-016 属同一族（挂钟时间与时间点混用），但 ISSUE-016 覆盖的是日期存储，这里覆盖的是排程比较。

## 四、教训（都写进了对应文档，避免重复踩）

1. **静态校验替代不了装机运行**：`INTERNET` 缺失（ISSUE-015）与通知图标被裁（ISSUE-017）都是"静态检查通过、装机才发现"的同类问题。`release.md` 的必查清单本次因此新增了"通知图标必须在包内"。
2. **悄悄吞掉的异常代价极高**：ISSUE-017 的定位成本几乎全部花在"不知道失败原因"上；在 catch 里加一条开发日志后，根因一次就出来了。
3. **「没写 `shrinkResources`」推不出「不裁资源」**：实测 release 包 1039 个资源 / debug 包 1391 个（`abc_*` 分别为 335 / 687），release 确实会裁掉无人引用的资源。`release.md` 里那条旧推论已更正为"看实测，不看配置"。
4. **验收记录必须写明设备时区**：ISSUE-018 只在设备时区与校园不一致时才发作，而这个模拟器恰好是 GMT。此前把它的时区记成 `Asia/Shanghai`，属于记录失真。
5. **统计方法本身要验证**：`dumpsys alarm` 的待触发区与历史区混在一起，初版统计口径偏高；换成按告警头行匹配后才准确。
